Local execution · Native subscription authentication

Codex subscription auth.
Implemented, not signed off.

A change report for the fullsend fork: use the official Codex client with an operator’s ChatGPT subscription, while keeping reusable account credentials outside the agent sandbox.

EXPERIMENTAL · VERIFICATION OPENImplementation exists in the working tree. It is not merged or released.

Not ready for real-account use. Integrated review found two credential-upload bypasses, an expanded-upload bounds gap and two cleanup-verification gaps. Fixes and regression tests are in progress; they have not passed re-review. Tests use synthetic profiles and subprocess fixtures. No personal ChatGPT credentials, real login, real upstream OAuth refresh or real model request were used. The full regression run is not green.

02

What changed

  • Explicit CLI authority

    Added --codex-auth chatgpt, --codex-auth-profile and --codex-binary. Native mode also requires the explicit --runtime codex flag. Repository config and environment variables cannot opt into account access.

    internal/cli/run.go · run_codex_subscription*.go
  • Runner-owned broker

    The official app-server owns refresh. The broker validates the selected profile, native refresh authority, token expiry and account/user continuity. A private persistent lock serializes access to the canonical credential directory.

    internal/inference/codexauth/
  • Native runtime branch

    The constructor holds trusted identity metadata. Launch regenerates sandbox auth with an issued stable handle, an empty refresh value and a noncredential identity stub. It pins native routes and scrubs alternate auth and routing variables.

    internal/runtime/codex_subscription.go · codex bootstrap/config/run/integrity helpers
  • Activation & revocation

    A new SDK helper updates credential value and expiry together. The caller checks the intended sandbox, provider and attachment identity against activation evidence before use. Refresh failure cancels the run. Cleanup requests revocation even with --keep-sandbox, but the new review found verification gaps that still block sign-off.

    internal/sandbox/provider_activation.go · CLI provider/refresh/revoke helpers
  • Upload & log guards

    Added private-profile checks and final-byte inspection for configured host files. Review found an unguarded implicit upload and inconsistent BOM handling; those protections are not complete. Detection handles partial native envelopes and unrelated overflowing JSON numbers. Sensitive wrappers redact formatting output; collected OpenShell logs pass through credential redaction.

    internal/cli/host_file_credentials.go · native bootstrap guards · run_log_redact_test.go
  • Tests & documentation

    Added synthetic process, locking, malformed-input, upload, lifecycle and CLI tests. Updated CLI/runtime/auth references, reserved-environment tests and sandbox-env schemas. The architecture decision is isolated in its own documentation PR.

    docs/cli/run.md · docs/runtimes/codex.md · auth/runtime guides · sandbox-env schemas

Security findings already corrected

Restricted persisted OAuth issuer/client provenance; enforced canonical case-sensitive JWT fields and strict expiry/encoding; fixed credential detection when unrelated JSON numbers overflow; moved the cooperative lock from ancestor HOME into canonical CODEX_HOME; added formatter coverage for unsupported verbs, pointers and nested exported containers; scrubbed inherited organization/project routing variables.

05

What remains open

  • 01
    Close both credential-upload bypasses · high severity

    An implicit org-level AGENTS.md symlink can point into the private profile and reach an unguarded upload. Separately, BOM-prefixed credential JSON can evade the native-only prohibition when durable uploads are allowed. Both paths need canonical checks, consistent normalization and checked-byte snapshots.

  • 02
    Bound final expanded uploads

    The expanded path reads a final source without the native bound and can amplify substitutions. Source growth and output construction both need limits before the checked snapshot is transferred.

  • 03
    Make cleanup readbacks fail closed

    Provider absence must reject malformed pagination and entries. Detach receipts must distinguish an explicitly empty provider ID from missing, null or wrong-typed data. Both checks need duplicate-key rejection and strict required fields.

  • 04
    Re-run integrated verification

    The reported defects need RED-to-GREEN regressions and independent re-review. The assembled CLI test passes normal, retained-sandbox and failed-run scenarios before these fixes; it must pass again afterward. Synthetic wiring tests are not real model or proxy verification.

  • 05
    Stabilize the gateway success-path tests

    Diagnostic-only instrumentation reproduces the exact timeout on base production code. A 20 ms settle deadline starts before a real subprocess read; expiration stops the worker, so the outer wait cannot recover. Fully untouched base test bytes pass in the bounded comparison. A narrow test-only settle allowance is being added; no native-auth regression is established.

  • 06
    Publish the implementation separately

    This HTML report and the architecture decision do not publish or merge the authentication implementation. A code PR still needs verified scope, migration notes and explicit proof limits.

Initial scope is intentionally narrow

  • Manual local execution, one context, no delegation, and no host-side pre/post/validation scripts.
  • No automatic import of a personal Codex profile and no silent fallback to API authentication.
  • Retaining a sandbox does not retain its subscription capability.
  • Claude subscription support, CI/remote subscription use and production entitlement verification are outside this initial slice.
