Codex subscription auth.

A change report for the fullsend fork: use the official Codex client with an operator’s ChatGPT subscription, while keeping reusable account credentials outside the agent sandbox.

EXPERIMENTAL · VERIFICATION OPENImplementation exists in the working tree. It is not merged or released.

Not ready for real-account use. Native-mode tests use synthetic profiles and subprocess fixtures. No personal ChatGPT credentials, real login, real upstream OAuth refresh or real model request were used. The full regression run is not green.

02

What changed

  • Explicit CLI authority

    Added --codex-auth chatgpt, --codex-auth-profile and --codex-binary. Native mode also requires the explicit --runtime codex flag. Repository config and environment variables cannot opt into account access.

    internal/cli/run.go · run_codex_subscription*.go
  • Runner-owned broker

    The official app-server owns refresh. The broker validates the selected profile, native refresh authority, token expiry and account/user continuity. A private persistent lock serializes access to the canonical credential directory.

    internal/inference/codexauth/
  • Native runtime branch

    The constructor holds trusted identity metadata. Launch regenerates sandbox auth with an issued stable handle, an empty refresh value and a noncredential identity stub. It pins native routes and scrubs alternate auth and routing variables.

    internal/runtime/codex_subscription.go · codex bootstrap/config/run/integrity helpers
  • Activation & revocation

    A new SDK helper updates credential value and expiry together. The caller checks the intended sandbox, provider and attachment identity against activation evidence before use. Refresh failure cancels the run. Cleanup revokes access even with --keep-sandbox.

    internal/sandbox/provider_activation.go · CLI provider/refresh/revoke helpers
  • Upload & log guards

    Native mode excludes private-profile paths and inspects the final host-file upload bytes. Credential detection handles partial native envelopes and unrelated overflowing JSON numbers. Sensitive wrappers redact formatting output; collected OpenShell logs pass through credential redaction.

    internal/cli/host_file_credentials.go · native bootstrap guards · run_log_redact_test.go
  • Tests & documentation

    Added synthetic process, locking, malformed-input, upload, lifecycle and CLI tests. Updated CLI/runtime/auth references, reserved-environment tests and sandbox-env schemas. The architecture decision is isolated in its own documentation PR.

    docs/cli/run.md · docs/runtimes/codex.md · auth/runtime guides · sandbox-env schemas
03

Where credentials live

The boundary is credential custody, not local model inference. Requests still go to the native ChatGPT service.

Trusted runner & local gateway
  1. Dedicated private profileOfficial login state stays in the selected host directory.
  2. Official Codex brokerOwns refresh; the runner validates identity and remaining lifetime.
  3. Scoped OpenShell providerHolds the current access credential and enforces handle binding and expiry.
Agent sandbox
  1. Stable reference onlyIssued provider handle plus noncredential account metadata. No reusable host access, refresh or ID token is seeded.
  2. Native requestThe proxy resolves the permitted handle at the allowed destination. The sandbox does not perform host OAuth refresh.
Subscription scope · chatgpt.com:443POST /backend-api/codex/responsesGET /backend-api/wham/accounts/check

Workspace discovery needs the GET route even with a forced workspace. The scope above concerns subscription traffic, not every unrelated forge or package request. Same-user host code remains trusted: environment filtering does not isolate a credential file from arbitrary host scripts.

Security findings already corrected

Restricted persisted OAuth issuer/client provenance; enforced canonical case-sensitive JWT fields and strict expiry/encoding; fixed credential detection when unrelated JSON numbers overflow; moved the cooperative lock from ancestor HOME into canonical CODEX_HOME; added formatter coverage for unsupported verbs, pointers and nested exported containers; scrubbed inherited organization/project routing variables.

05

What remains open

  • 01
    Close the integrated verification gates

    Accept the final authority/upload and provider-lifecycle reviews. Verify the assembled CLI path without replacing its production host-session startup.

  • 02
    Classify the gateway timeout

    The latest unchanged-base CLI run passes, while the modified full root run has one gateway handoff timeout. Other historical base runs have a related timeout. That is not enough to label the exact remaining failure conclusively pre-existing.

  • 03
    Publish the implementation separately

    This HTML report and the architecture decision do not publish or merge the authentication implementation. A code PR still needs verified scope, migration notes and explicit proof limits.

Initial scope is intentionally narrow

  • Manual local execution, one context, no delegation, and no host-side pre/post/validation scripts.
  • No automatic import of a personal Codex profile and no silent fallback to API authentication.
  • Retaining a sandbox does not retain its subscription capability.
  • Claude subscription support, CI/remote subscription use and production entitlement verification are outside this initial slice.
